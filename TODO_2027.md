# 2027 To-Do

Everything to do before the 2027 season, including expanding the contest from NorCal to the whole USA.

Sections are in rough order: make the decisions first, because most of the code work depends on them.

---

## 1. Decisions to make first

- [ ] **Name and brand.** "NorCal Hike & Fly" appears in the site header, About page, Overview, README, email sender name, email templates, logo, domain (`norcalhf.com`), contact email (`norcalhf@gmail.com`), the upload worker URL (`tracklog-upload.norcalhf.workers.dev`) and the merge tool (`merge.norcalhf.com`). Decide whether to rebrand (e.g. "US Hike & Fly") or keep NorCal as the flagship name with a national contest under it.
- [ ] **Domain.** If rebranding, register the new domain, point it at Cloudflare Pages and keep `norcalhf.com` redirecting so old links (including the Past Seasons leaderboard links) keep working.
- [ ] **Season dates.** 2026 ran April 4 – October 31 with uploads accepted through November 6. Flying seasons differ a lot across the US (e.g. the Southwest flies in winter, the Northeast doesn't), so decide whether one national window still works.
- [ ] **Daily time window.** Scoring trims tracks to 6am–6pm **local time** (`COMPETITION_START_HOUR` / `COMPETITION_END_HOUR` in `scoring/hf_scoring.ts`). Local time already works across time zones, but check the window makes sense everywhere (e.g. Alaska and the northern states in summer).
- [ ] **Regions / leaderboards.** Decide whether there is one national leaderboard, regional leaderboards (e.g. by state or by West / Rockies / East), or both. This affects data, scoring scripts and the leaderboard page (see section 4).
- [ ] **Divisions.** Keep EN-B / EN-C / EN-D? Consider an EN-A / ground-handling-friendly division or a hiking-only category for a bigger field.
- [ ] **Number of scoring flights.** 2026 counted each pilot's top 4 (`tracklog_handler/src/user_data.ts:46`; the variable is misleadingly named `top2`). Decide the 2027 number.
- [ ] **Friends bonus.** Needs 4+ tracks starting at the same place and time (`FRIENDS_RADIUS_KM` / `FRIENDS_MIN_GROUP` in `tracklog_handler/src/score.ts`). Check it still works for regions with few pilots, or scale it by region.
- [ ] **Prizes and sponsors.** A national contest is a good time to find sponsors (gear brands, schools, clubs).
- [ ] **Running it.** With pilots across the country, decide whether to recruit regional volunteers to help with questions and verifying tracks.

## 3. Registration and accounts

2026 registration was manual: pilots were added to `users.json` by hand (username, passphrase, division, email) and sent credentials with `email_tool`. That won't scale to a national field.

- [ ] **Self-serve sign-up.** Add a registration form (username, email, division, home region) backed by the worker, replacing hand-edited `users.json`.
- [ ] **Credentials.** Passphrases are stored in plain text in `users.json` in R2, and some are just the username. Store them hashed, or move to emailed magic-link logins so there's nothing to forget or leak.
- [ ] **Real names.** `users.json` has no real-name field, so leaderboards and the Past Seasons page show usernames. Add a display name at registration.
- [ ] **Division changes.** Rules say pilots can move up a division by email. Consider handling this in the account instead.
- [ ] **Mailing list.** Use the 2026 Register signups (`npm run -s export-mailing-list`) to announce 2027.
  - [ ] Decide whether to make the list fully private. Right now anyone who already knows an address could check whether it signed up. To close that, move `mailing_list/` to a private bucket or key it with a worker secret (HMAC).
  - [ ] Add an unsubscribe link to announcement emails.
- [ ] **Email sending.** `email_tool` sends through a personal Gmail account. Gmail sending limits (roughly 500/day) and deliverability will be a problem for a national list. Move to a transactional email service (e.g. Resend, Postmark, Amazon SES) from the contest's own domain.
- [ ] **Waiver / liability.** Hike and fly is risky. A national contest with strangers should have a signed waiver at registration and a clear statement that the contest doesn't supervise flying. Check whether USHPA membership should be required.

## 4. Expanding to the whole USA

### Rules
- [ ] **Geographic region.** `Rules.md` says "All tracks must be completed within California or the surrounding area." Rewrite for the USA (and decide on Alaska, Hawaii and flights that cross into Canada or Mexico).
- [ ] **Regional enforcement.** If there are regional leaderboards, decide whether a flight counts for the pilot's home region or the region it was flown in, and enforce it in scoring (the launch point is already known from the track).
- [ ] **Airspace and local rules.** Add a line that pilots are responsible for airspace, site rules and permits wherever they fly. National parks and wilderness areas have different rules than California sites.
- [ ] Review the whole rules page for California-specific wording.

### Scoring and data
- [ ] **Time zones.** IGC files use the `HFTZNTIMEZONE` header. GPX files call the free `timeapi.io` API for every track (`scoring/hf_scoring.ts:43`). With more pilots this external API could rate-limit or go down. Look up time zones offline (e.g. the `tz-lookup` package) instead.
- [ ] **Leaderboard data.** Add a `region` to each flight and pilot, and either build one `leaderboard.json` per region or add a region filter alongside the division filter on the leaderboard page.
- [ ] **Hiking/vertical categories.** Decide whether these are national or per region.

### Infrastructure and scale
- [ ] **Automate processing.** Scoring currently runs when someone runs `npm run process` locally. Run it on a schedule instead (Cloudflare Cron Trigger or a scheduled GitHub Action), or on each upload.
- [ ] **Upload worker cost.** The duplicate check lists every one of a user's files and `head`s each one on every upload. Fine for 10 flights, slow for heavy users. Store a hash index instead.
- [ ] **Rescore time.** `npm run rescore` re-scores every track one after another. Check how long it takes with 10x the tracks, and add parallelism if needed.
- [ ] **Rate limiting.** The upload limit is 10/min per IP, shared with `/subscribe`. Groups uploading from the same launch Wi-Fi or cell tower could hit it, and the Register form adds traffic.
- [ ] **Map tiles.** The flight map (`site/src/components/Flightmap.astro`) loads tiles straight from OpenTopoMap's free, volunteer-run servers, which discourage heavy use. Move to a provider with a proper free or paid tier (e.g. Thunderforest, MapTiler, Stadia) before traffic grows.
- [ ] **7-day upload rule.** "Tracklogs must be submitted within 7 days" is only checked in the browser (`Scoring.astro:138`). The worker doesn't check it, so anyone uploading directly can get around it. Add the check to the worker.
- [ ] **Cloudflare plan limits.** Check R2, Workers and KV free-tier limits against the expected number of pilots.
- [ ] **Backups.** Schedule `npm run backup` instead of running it by hand.
- [ ] **Monitoring.** Get alerted when the worker errors or processing fails, so problems aren't found by pilots.

### Community and promotion
- [ ] **Chat group.** The NorCal Telegram group won't work nationally. Consider regional channels, or a Discord with a channel per region.
- [ ] **Outreach.** Announce through USHPA, regional clubs, Facebook/Reddit hike and fly groups, and the 2026 pilots and mailing list.
- [ ] **Help docs.** The Tracklog Help and merge tool are fine as-is, but add an FAQ to cut down on email questions.
- [ ] **Photos.** Collect season photos as the prologue did, with one shared album per region.
